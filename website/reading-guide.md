# 阅读指南

这本白皮书围绕一个共同问题展开：怎样把模型能力变成可以交付、运行、治理和持续改进的 Agent 系统。你可以从头阅读，也可以带着当前的工程问题进入相应章节。

## 第一次系统了解 Agent

先读[开发者调研报告](/survey.html)，了解企业落地的现状；再读[架构篇](/architecture/)，建立 Model、Harness 和 Agent Platform 的共同语言。[构建篇](/build/)进一步解释任务、信息与行动怎样组成一个可工作的 Agent。

推荐顺序：调研报告 → 第1—2章 → 第3—6章 → 第13—16章。

## 正在把 Agent 接入生产

从[运行篇](/run/)开始，关注执行环境、持久状态、网关和长任务。随后进入[治理篇](/governance/)，检查观测、授权、资产管理和上线验证是否覆盖完整任务。

推荐顺序：第7—9章 → 第10章 → 第13—14章 → 第18—23章。

## 正在建设多 Agent 系统

先通过[第4章](/build/chapter-04.html)和[第6章](/build/chapter-06.html)明确任务、委派和行动边界，再读运行篇的[异步任务](/run/chapter-10.html)、[协作编排](/run/chapter-11.html)与[分布式通信](/run/chapter-12.html)，最后用观测与质量验证检查整体结果。

推荐顺序：第4—6章 → 第10—12章 → 第13、16章。

## 负责评估与持续优化

从[第18章调优总览](/optimization/chapter-18.html)建立数据飞轮的完整视图，再依次理解轨迹、数据处理、黄金数据集、Badcase 和受控自进化。需要改变模型本身时，再进入[第17章模型调优](/optimization/chapter-17.html)。

推荐顺序：第13章 → 第18—23章 → 第17、24章 → 相关实践案例。

## 负责选型或项目立项

先读调研报告和第1—3章，明确业务目标与构建方式；按行业或岗位进入[实践篇](/cases/)，对照投入、边界和交付结果；最后读[第30章](/outlook/chapter-30.html)，理解平台演进的长期方向。

## 怎样使用这个阅读站

- 左侧目录组织全书篇章，右侧目录定位当前章节的小节。
- “搜索全书”支持中文主题和英文术语，结果可以直接定位到相关段落。
- 文末的上一篇和下一篇可以连续阅读；阅读位置保存在当前浏览器，首页可继续上次阅读。
- 点击正文图片可放大查看。架构图支持单独打开，宽表格和代码块可以横向滚动。
- 可以调整正文字号、切换明暗主题，或打印当前章节。
- 发现内容问题时，可从页面的反馈入口提交 Issue，或通过“在 GitHub 上完善本页”参与编辑。
